## Summary

- Traffic throughput dropped significantly compared to 2.6.0: HTTP requests/sec fell by roughly half, and HTTPS requests/sec fell by about a third. Average and max latency also increased noticeably across both protocols.
- No non-2xx or 3xx responses were reported for either HTTP or HTTPS, an improvement over 2.6.0 where HTTPS reported a significant number of non-2xx/3xx responses.
- Memory improved for NGINX, but was worse for NGF
- New error pattern in nginx-gateway: a number of RBAC "forbidden" errors were logged when the controller attempted to watch cluster-scoped resources (NginxProxy, ListenerSet, HTTPRoute, TCPRoute, UpstreamSettingsPolicy, ProxySettingsPolicy, Pods) and to get the leader-election lease, all within a short window. This differs from the "config apply failed" errors seen in 2.6.0 and points to a permissions/RBAC issue rather than a config-apply problem. Could be due to cluster upgrades, but unknown. Likely transient.
- No nginx upstream errors (timeouts, premature closures, no live upstreams) were observed, an improvement over 2.6.0 which had a burst of such errors.
